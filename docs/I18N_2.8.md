# S5 Studio 2.8 — Internationalization

[English README](../README.md) · [README italiano](../README.it.md) · [Documentation](README.md)

## Using the application

Choose **Lingua / Language** in the top toolbar: **Italiano** or **English**. Italian is the default, independent of Windows language. The main editor updates immediately, including dynamic panels and menus; the selection is retained for the next launch. Native dialogs created afterward use the selected Qt translation. The legacy Qt editor reads the same preference at startup.

The setting belongs to the application, not a watchface project:

| Execution mode | Configuration |
| --- | --- |
| Windows EXE | `%LOCALAPPDATA%/S5Studio/settings.json` |
| Python source checkout | `<repository>/data/settings.json` |

```json
{
  "language": "it"
}
```

Use `"en"` for English. A missing, malformed or unsupported preference falls back to Italian. Saving the language preserves existing compiler and unrelated settings; it uses a temporary file followed by replacement. `settings.example.json` documents the initial configuration. Runtime preferences are not embedded into the distributed EXE.

**Project integrity:** changing language does not translate user-defined project/layer/style/catalog names, rename assets, replace source identifiers or change sensor/calibration values. It does not set the watch's language. MON–SUN and the project's English month labels keep their existing watchface behavior. All seven watch Lua modules remain byte-identical to 2.7; this release changes desktop presentation and preferences.

## Qt: tr, TS and QM

Native window/dialog titles, buttons, field labels, prompts and file filters use `self.tr()`. Variable messages are translated before formatting, for example:

```python
self.tr('Progetto salvato: {v0}').format(v0=path)
```

Avoid `self.tr(f'...{value}...')`: extraction tools cannot establish a stable source message for the already formatted string. Combo-box labels are translated independently from their item data; application logic uses the original item data rather than translated display text.

| File | Purpose |
| --- | --- |
| `translations/s5studio_it.ts` | Italian source/base catalog, editable in Qt Linguist |
| `translations/s5studio_en.ts` | English Qt catalog, with contexts and source references |
| `translations/s5studio_it.qm`, `s5studio_en.qm` | Compiled application catalogs |
| `translations/qtbase_it.qm` | Qt's upstream Italian catalog for standard native controls |
| `translations/ui_strings.py` | Generated `QT_TRANSLATE_NOOP` markers for loop-supplied native labels |
| `s5studio/i18n.py` | Translator installation, lifetime management and offline catalog loading |

The application retains the installed `QTranslator` objects for their required lifetime. Previous translators are removed when switching languages. Italian application source text is the default fallback; Qt's standard Italian controls use its own upstream catalog. Completed context-specific TS translations are preserved when updating the catalogs.

## Frontend: JSON and data-i18n

Frontend messages live in **`locales/it.json`** and **`locales/en.json`**. They use Italian source text as stable message IDs, a gettext-style convention. Identity entries in `it.json` retain the original Italian wording; English entries carry the translated presentation. Parameters such as `{count}` or `{v0}` are retained in both languages.

```html
<span data-i18n="Salva progetto">Salva progetto</span>
<input data-i18n-placeholder="Cerca set" placeholder="Cerca set">
<span data-i18n-skip>My user-defined layer name</span>
```

```javascript
t('{count} livelli', {count: 5}); // "5 layers" in English
```

`frontend/app.js::loadLanguage()` loads the selected JSON catalog at startup and after a user change. Under the EXE's `file:` origin, it uses the **local QWebChannel bridge**, which reads the bundled JSON; this avoids unsupported Chromium `fetch(file:)` requests. An HTTP-hosted frontend can use `fetch()` with the same JSON files. There is no online translation service or network requirement.

`frontend/i18n.js` applies explicit `data-i18n` keys and localized title/placeholder/ARIA/alt attributes. It also translates known source text in newly rendered interface nodes. A scoped MutationObserver processes changed nodes; it does not translate input values, image payloads or project data. Custom dropdowns copy already localized option labels once, preserving their original values. User-content nodes are protected with `data-i18n-skip` and dedicated selectors.

Attach `data-i18n` to a **text leaf**, not a container whose icons or controls must remain children: the explicit key owns that leaf's text. Use `data-i18n-title`, `data-i18n-placeholder`, `data-i18n-aria-label` or `data-i18n-alt` for attributes. Missing catalog entries fall back to Italian/source text, so a partial translation does not produce an empty interface. Technical diagnostics from external tools or unregistered backend messages can retain their original language.

## Updating translations

```powershell
python -X utf8 scripts/update_translations.py
python -X utf8 scripts/update_translations.py --compile
```

The script extracts Python/HTML/JavaScript presentation messages, invokes the installed PySide6 **lupdate**, updates the base `.ts`, retains existing JSON entries and completed TS translations, and checks placeholder consistency. `--compile` invokes **lrelease** to generate `.qm` files and copies Qt's Italian base catalog. The PySide6 development installation supplies these tools; they are not bundled as executable developer tools in S5 Studio.

Edit English frontend text in `locales/en.json`; edit native context-specific translations in `translations/s5studio_en.ts` using Qt Linguist or a text editor. New Qt messages are initially seeded from the JSON catalog where possible; existing completed TS translations remain authoritative for their context. Do not edit generated `ui_strings.py`. For an additional language, register its code in the settings/frontend supported-language lists and extend the extraction/packaging language list before distributing its JSON/TS/QM files.

The packaging script runs extraction/compilation before staging the runtime and includes both JSON catalogs, compiled Qt catalogs and `frontend/i18n.js`. Translation failure stops packaging. No original watchface assets or compiler code are modified by extraction.

Qt references: [Translating Applications](https://doc.qt.io/qtforpython-6/tutorials/basictutorial/translations.html), [QTranslator](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QTranslator.html), [Qt Linguist workflow](https://doc.qt.io/qt-6/linguist-translating-strings.html).
